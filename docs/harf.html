Messages
 
The problem

Nobody forgets the language.
Everybody forgets the layout.

You switch to English to paste a link, then come back to write in Arabic and start typing. Nothing warns you. The first sign anything is wrong is a line of nonsense — and every key you pressed was already the right key.

what appears
hgsghl ugd;l
→
what you meant
السلام عليكم

The old fix

Select the line. Delete it. Find the layout switcher. Type the whole thing again. A dozen times a day.

Both directions

English typed on the Arabic layout comes out as اخص ه — and turns back into "how i" just as readily.

The real cost

Not the seconds. The interruption — you lose the sentence you were composing while you fight the keyboard.

How it works

It reads the keys, not the letters.

The letters on screen are already the mistake. The physical key you pressed is identical in both layouts — so what you meant is recoverable exactly, with no guessing and no autocorrect-style rewriting of your words.

01 Records keys

Every keystroke is stored as a key position, not a character. Nothing is read off your screen and nothing is written to disk.

02 Reads it twice

On a one-second pause, that key sequence is rendered through both layouts using macOS's own tables — real text, not a substitution table.

03 Scores and acts

Both readings are scored offline against bundled dictionaries. A clear winner is rewritten silently; a close call is offered as a card you accept with Tab.

Safety

It deletes your text.
So it is careful about it.

An app that edits what you wrote without asking has to earn that. Every one of these can only ever cancel a rewrite — none of them can cause one.

Password fields
Secure fields are never captured, and the keystroke history is purged the moment one is detected.
Terminals
Suggest-only by default. A wrong rewrite in a shell is worse than a wrong rewrite in a sentence.
Verify before deleting
The app is asked what sits in front of the caret. If the answer disagrees with what Harf recorded, it refuses and offers a suggestion instead.
Only the trailing run
A bilingual line is never wholesale rewritten — only the stretch that reads better under the other layout.
Code is left alone
URLs, paths, emails, identifiers, version strings and shell commands are recognised and skipped.
One key undoes it
⌥⌘Z restores exactly what you typed and switches the layout back. ⌥⌘P pauses everything, instantly.
No network
There is no networking code in the app at all. The dictionaries ship inside it.
Details

Quiet by default.

Fast enough to miss

A full sentence is replaced in about 160 ms. You see the corrected text, not the correction happening.

Per-app control

Set any app to Normal, Suggest-only, or Off. Terminals and password managers are already configured for you.

Three sensitivities

Conservative, Balanced or Eager — one slider that moves every threshold together, so there is a single thing to reason about.

Menu bar only

No Dock icon, no windows in your way. Roughly 0% CPU while you type.

Install

Four steps, once.

Get it

Download the app, or clone the repository and run make install to build from source.

Grant two permissions

Input Monitoring lets Harf see the keys you press. Accessibility lets it replace the text. It cannot work with only one.

Type something wrong

With the English layout active, type hgsghl ugd;l and pause for a second. It becomes السلام عليكم.

Forget about it

That is the whole product. You stop noticing that you ever forgot to switch.

Questions

Reasonable doubts.

Does it send my keystrokes anywhere?

No. There is no networking code in the app — you can check, the source is public. The word lists are bundled inside the app and every decision is made on your Mac. Nothing is written to disk either; the buffer holds at most 200 keys in memory and is cleared constantly.

What if it rewrites something I meant?

⌥⌘Z puts it back exactly and switches the layout back, for 30 seconds after any fix. It also stops re-fixing that text so it cannot bounce. In practice it is conservative: normal writing in either language never triggers anything.

Will it mangle my code or terminal commands?

URLs, file paths, emails, camelCase and snake_case identifiers, version strings and anything with digits touching letters are all skipped outright. Terminals are suggest-only by default, so nothing is ever rewritten in a shell without you pressing Tab.

Does it work in every app?

Most. Some apps that draw their editor in a web view cannot tell Harf what is in front of the caret, and there it offers a suggestion rather than rewriting silently — deliberately, because deleting text it cannot verify is how a tool like this corrupts your work.

Why not just autocorrect?

Autocorrect guesses at what you meant from letters that are already wrong. Harf does not guess: it replays the exact keys you pressed through the other layout, so the result is precisely what you would have typed had the layout been right.
